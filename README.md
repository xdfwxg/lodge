# Lodge

> Lodge：以寮为本体的多Agent编码工作台，一室一任务，席位驻于寮内，隔离交付、可验可溯。
> 一寮承事，灵侣偕居，功成俟鉴

**Room-first multi-agent coding workspace**

Lodge 将寮（Lodge）作为一等公民本体。席位驻于寮中，对话只是寮内日志；目标、席位配置、工作区隔离、验收证据全部依附于寮。

- 🏠 **Lodge** = 独立任务房间（本体）
- 🧑‍💻 **Seat** = Agent席位
- ✅ **acceptance_cmd**：可执行命令作为验收证据
- 🛡️ **工作区策略**：git 仓库用 worktree；普通目录原地修改，不复制；它不是文件系统沙箱
- 📦 **交接包**：真实房间可导出 BRIEF/结论/对话/事件/证据；当前实例不提供“打开交接记录”导入入口
- 🧪 **示例**：[examples/rooms](examples/rooms) 有可直接打开的样本（3 个模拟 + 1 个真实）
- 📌 **项目约束**：仓库根 `LODGE.md` 写架构与约定，建房时可读取并带入 BRIEF
- 🧩 **本地模板**：`.crew.yaml` / `.json` 导入预览，带席位与提示词；权限仍由角色派生
- 📊 **用量**：24 小时到 12 个月，花费/Token/缓存命中/回合与房间排名
- 🖥️ **macOS 桌面版**：`npm run desktop` 开发启动，`npm run package:mac` 打 zip；详见 [docs/macos-desktop.md](docs/macos-desktop.md)

## 现在能做什么

- **一句话开房**：规划师先给 done、分工、验收方式和最多 3 个问题；人确认一次直接开工。
- **固定三人小队**：规划师、执行者、验收员；单人、自定义编制和模板属于未开放扩展。
- **目标与阶段**：对齐 → 交付 → 验收与结论；每阶段一张结论卡，结果不对可重审目标并返工；未开始阶段可增删改和重排。
- **房型策略**：任务房（默认）、圆桌派队（讨论阶段只读）、存档房；房型由策略注册表提供，不在核心逻辑里写分支。
- **真实执行**：本地 CLI 在 git worktree 或普通目录原地干活；多执行并行后集成。
- **证据验收**：验收命令、退出码、diff/文件清单；多验收席位全部 PASS 才允许人签字。
- **权限与审批**：写工具按席位拒绝；push/安装/删除/发送/网络动作挂起等人批准，10 分钟无人处理会暂停房间；验收命令在一次性副本里跑。
- **成本与注意力**：房间/全局预算到线暂停；每个房间最多一个“待你处理”信号。
- **交付与交接**：交付单、Markdown 导出、房间记录 commit；交接包可导出。
- **查看与审计**：目标岛、复盘、资源面板、用量时间序列、事件/证据留痕。
- **桌面**：macOS Electron ad-hoc zip；基座和 CLI 不打入 app。

## 为什么不一样

1. **房间是本体，不是聊天**：目标、阶段、证据、结论、commit 都在 `.crew/rooms/<id>/`；换席位、引擎或模型，房间记录还在。
2. **验收是命令**：交付型阶段必须有 acceptance 命令、退出码和 diff/文件清单；模型自述不算通过，最后仍由人签字。
3. **一张开工卡**：规划师给 done、分工、验收和最多 3 个问题，人确认一次；默认固定三人小队（规划师/执行者/验收员），单人暂不开放。
4. **本地真实执行**：直接跑你已登录的 CLI；git 用 worktree，普通目录原地修改；多执行并行后集成。
5. **权限和审批在工具面**：planner/verifier 不能写；外部 push/安装/删除/发送/网络动作挂起等人批准。
6. **交付可带走**：结论 commit 带房间记录；交接包可导出，导入入口暂不提供。
7. **诚实边界**：没有第二引擎就标独立性降级；不是通用沙箱、没有 macOS 自动更新，就不说。

## 现在还不是什么

- 不是云端或多人 Org；首版是单用户、本地仓库、本地 CLI。
- 不自动路由、不自动执行；调度台只建议，人确认。
- 不是通用文件系统沙箱；worker 的 `exec` 仍能写自己的工作区，OS 级 venv/数据库/端口强制隔离未做。
- 跨厂商盲审依赖第二台可用 CLI；没有时显式标“独立性降级”。
- 发言配额只记录、未强制；分叉会议未做；跨实例交付自动同步未做。
- macOS 不公证、不自动更新；Windows/Linux 只加了打包配置，未真机验证。
