# Lodge

> 房间是本体，成员是房间里的人，Bot 是这个人现在的身体。

**本地优先的房间式 AI 工作台。** 说清一件事，房间替你留下目标、过程、结果和证据；换成员、换引擎、换模型，房间还在。

> 这是一台优秀的机器，还不是一个优秀的产品。
>
> 只保留一个时刻：早上把目标交进去，晚上工作上桌。岛是唯一漂亮的东西，让它讲故事；其余的东西，需要时再出现。不要让我看见工厂，只让我看见工作完成。

```text
聊天室 ──结论──▶ Gate ──开工──▶ 工作室
                                ├─ 规划师拆步骤
                                ├─ 执行官交付
                                ├─ 验收员复核
                                └─ 人签字
```

## 为什么做 Lodge

大多数 AI 协作产品在卖“更聪明的聊天”。Lodge 卖的是另一件事：**这次工作有记录、能验收、能交给下一个人。**

- **房间是本体**：目标、成员、阶段、证据、结论、工作区都属于房间，不属于某一次对话。
- **交接有记录**：谁把什么交给谁、交付了什么、证据是什么，一条 Assignment 说完。
- **验收是证据**：命令、退出码、diff 和人的签字；模型自述不算通过。
- **本地优先**：跑在你自己的仓库和已经登录的 CLI 上，不把工作搬到云上。
- **换身体不换职责**：成员是身份，Bot 是 AI 成员当下的执行身体；换引擎、换模型、换 runtime，房间记录还在。

## 三个对象

### Room · 房间

一个房间一件事。房型在建房时确定，运行期不切换。

- **聊天室**：可以独立讨论、收结论；需要动手时，把结论转成工作室任务。
- **工作室**：分步执行、独立复核、人签字、可交付、可建子房；结果可以带回聊天室继续打磨。

### Member · 成员

成员是房间参与者：人，或 AI。

- 角色、权限、职责、写入范围都属于成员，不属于身体。
- 规划师决定下一步，执行官交付这一步，验收员判断这一步，人决定走不走。
- 没有全局成员表；成员属于房间。

### Assignment · 交接

一次交接就是一条 Assignment：发起人、接收人、要做什么、走到哪一步、结果和证据。

- 状态只沿一条链走：创建、送达、交付、通过或退回。
- 返工新建一条，指向被退回的那条；复核指向它复核的那条。
- 证据只记引用，不复制正文。
- 界面上的消息只是投影；派发状态和任务列表都从 Assignment 算。

## 能做什么

- **一句话开房**：说清目标，确认成员和验收方式后开工。
- **规划、执行、复核**：规划师拆步骤，执行官在自己的工作区里做，验收员独立复核。
- **并行执行**：多个执行官各在自己的 worktree 里做，结束后集成；冲突停下来交给人，打开冲突目录、解决并提交后继续验收。
- **证据验收**：产品从仓库里认出能跑的检查，在一次性副本里跑；记录命令、退出码、输出、diff 和改动文件；认不出来就明说没有自动检查。
- **权限与审批**：写工具按成员拒绝；外部动作挂起等人批准。
- **子房**：父房把一件事交给子房，子房交付后回填结果和验收证据。
- **受控浏览器（可选）**：执行成员可在成员 MCP 里申请只读浏览器查公开网页；房间权限分“每次确认”和“房间免确认”两档。独立临时 profile，不接日常 Chrome，输入、脚本求值和本地文件默认关闭。
- **影子评审**：每间工作室内置的隐藏成员，换一个角度再看一遍；只在需要时出现，不进入验收判定。
- **交付卡**：做完先给结果——主视线只有交付物名称、检查结论和打开结果；路径、费用、版本、阶段过程都收在详情里，规划对话和命令折进「工作记录」。
- **目标岛**：房间顶部常驻一条玻璃胶囊，收起时先给当前步骤，展开就是目标、阶段、检查和结果；做完只写「已交付」。进度变化、需要你处理时原地形变，不打断阅读。

## 和别的多 Agent 产品有什么不同

| 常见形态 | Lodge |
| --- | --- |
| 一排 Bot，点进去聊天 | 一个房间，有目标、阶段、证据和交付 |
| 谁被 @ 谁说 | 成员有职责、权限和写入范围 |
| “我做完了” | 验收命令 + 退出码 + diff + 人签字 |
| 聊天记录就是结果 | 交付卡、证据和 commit 留在房间里 |
| 常驻云电脑 | 跑在你自己的仓库和本机 CLI 上 |
| 固定模型 | 引擎和模型可选；没有第二厂商就标模型自查 |

## 现在还不是什么

- 不是云端或多用户组织；当前是单用户、本地仓库、本地 CLI。
- 不是通用文件系统沙箱；没做的隔离不说做了。
- 不是通用记忆系统；会话记忆归 CLI，房间只留业务事实。
- 不做人格扮演；成员是职责与权限。
- macOS 只发 ad-hoc 签名 zip，不公证、没有自动更新；Windows/Linux 未真机验证。

## 快速开始

### 桌面版（macOS）

从 GitHub Releases 下载 zip；第一次打开被 Gatekeeper 拦下时，到“系统设置 → 隐私与安全性”点“仍要打开”。

桌面版内置基座和 Pi runtime，不需要再装 `crew-chat-base` 或系统 Node。Claude、Codex 等其他 agent CLI 仍需本机安装并登录；模型凭据不进 app 包。

### 源码运行

需要：

- Node 24+
- git
- 一个已经登录的 agent CLI
- 本机运行的 OpenMausBot 基座（独立仓库 `crew-chat-base`，默认端口 8799）

```bash
npm install
CREW_BASE_URL=http://127.0.0.1:8799 npm run dev
```

服务在 `http://127.0.0.1:8787`，UI 在 `http://127.0.0.1:5173`。

### 测试

```bash
npm test
```

测试使用独立的临时工作区，不污染你的 `~/CrewWorktrees`。
