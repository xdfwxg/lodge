# Lodge

> 房间是本体，成员是房间里的人，Bot 是这个人现在的身体。

本地优先的房间式 AI 工作台。说清一件事，房间替你留下目标、过程、结果和证据；换引擎、换模型，房间还在。

- **聊天室**：把一件事聊清楚，留下结论；要动手时，带着交接简报开一间工作室。
- **工作室**：你只说目标。规划师拆步骤、按工作包组队；执行官交付，验收员独立复核，默认一位、最多三位。
- **说好的事**：给房间留一个定时承诺，到点提醒或开工，也可以发到邮箱。
- **本地优先**：跑在自己的仓库和已登录的 CLI 上，数据不搬家。

工作室成员只在自己的工作副本里写；外部动作先问你；人只处理不可逆和不可验证的事。

```text
聊天室 ──交接简报──▶ 工作室
                       ├─ 规划师：拆步骤、组队
                       ├─ 执行官：按工作包交付
                       ├─ 验收员：独立复核
                       └─ 证据与交付 ──▶ 人只处理不可逆和不可验证
```

## 特色

- **房间是本体，不是一次会话**：目标、成员、阶段、证据和结论都属于房间；换引擎、换模型，房间和证据不动。
- **两种完整产品，一套底座**：聊天室只有讨论规则；工作室只有规划师/执行官/验收员。引擎隔离，不在房间里切换人格，也不引第三方编排框架。
- **成员是房间里的人，不是流程节点**：聊天室是固定六人班底，按话题请 2–6 位；工作室由规划师按工作包组队，执行官与验收员默认跨厂商。
- **本地优先**：跑在自己的仓库和已登录的 CLI 上；外部动作先问人，数据留在本机。

## 结果怎么保证正确

一句话：**不靠模型自评，靠契约、平台执行和独立验收。**

1. **先有契约**：规划师把目标拆成阶段，每步写清交付物和完成条件（clause），不写验收命令；执行官按工作包交付，必须带 `proof`（clause / run / expect）。
2. **平台替人跑证明**：每条 proof 由平台在验收员的只读副本里执行，记录真实退出码和输出；少一条、对不上，都不算完成。
3. **验收员独立复核**：验收员只看目标、改动和证据，不看执行对话；PASS 必须逐条覆盖要求（coverage），至少带一条 falsify（改动前失败、改动后通过），并写一条 diff 之外的风险；平台会核对它真的跑过。
4. **跨厂商复核**：验收员默认和执行官不同厂商；只有一家模型可用时明确标「模型自查」，不冒充独立复核。
5. **失败有边界**：退回最多 3 次；超时、额度用完、同一失败原地再现，就停下交给人。人只事后否决，不在中间点头。
6. **结果可回放**：房间、阶段、证据和判定都落库；消息只是投影，每一步都能对着证据复查，不靠聊天记忆。

它保证的不是「模型永不犯错」，而是：**没证据不算完成，错在哪看得见，人能事后否决。**

## 快速开始

### 桌面版（macOS）

从 GitHub Releases 下载 zip。首次打开被 Gatekeeper 拦下时，到「系统设置 → 隐私与安全性」点「仍要打开」。

桌面版内置基座和 Pi runtime；Claude、Codex 等其他 agent CLI 仍需本机安装并登录，模型凭据不进 app 包。

### 源码运行

需要 Node 24+、git、一个已登录的 agent CLI，以及本机运行的 OpenMausBot 基座（独立仓库 `crew-chat-base`，默认端口 8799）。

```bash
npm install
CREW_BASE_URL=http://127.0.0.1:8799 npm run dev
```

服务在 `http://127.0.0.1:8787`，UI 在 `http://127.0.0.1:5173`。

```bash
npm test               # 单测
npm run test:ui        # UI 端到端
npm run build          # 构建 UI
npm run desktop        # 构建后启动 Electron
npm run check:done     # 完成前验证：单测、UI 端到端、构建和门禁
npm run eval:rooms     # 真实房间评测（需要 Lodge 8787 和基座 8799）
```

测试使用独立临时工作区，不污染 `~/CrewWorktrees`。更多运行、打包、基座和 runtime 说明见 [docs/operations.md](docs/operations.md)。
