# Lodge 设计语言

Lodge 是一间房：说清楚，或做出来。工作室的界面回答三件事：现在在做什么、谁在做、结果怎么样；聊天室只回答：在聊什么、谁在说、聊到哪儿了。所有界面按这份文件走。

> 本文回答：界面和交互怎么做——字号、间距、颜色、组件、状态、文案。通用判断与**原则总表**见 [../思想.md](../思想.md#原则总表)；本文的原则是它在界面层的展开。

## 入口层级

一个产品只留三层入口，不再加第四个全局按钮：

| 层 | 入口 | 规则 |
|---|---|---|
| 主入口 | Lodge 输入框 | 用户只说一句话；主机器人判断是聊、是问、还是开房 |
| 手动出口 | 侧栏「＋」 | 直接打开「新房间」，默认工作室；聊天室是底部的次要入口「先聊聊」 |
| 上下文动作 | 聊天结论后的「转成工作室」、交付后的「聊一聊这次成果」「以后每周也这样」、项目页的「开下一轮」 | 只在结论或交付已经出现时出现，不提前占位 |

**不是入口的：**「更多选项」是同一个新建房对话框里的渐进披露；「调整成员」是对话框内部的设置；`⌘N` 只是「＋」的快捷键。它们不增加新的全局路径。

**已经删掉的重复入口：**「今天想做什么？」弹框、`GoalForm`、Lodge 底部的「更多选项」。它们和「＋」做同一件事，只是换了一个词。

**审计结果：** 目前全局入口只有 Lodge 输入和「＋」两个；聊天室只在结论后出现「转成工作室」，工作室只在交付后出现「聊一聊这次成果」「以后每周也这样」，开新一轮直接在输入框说。符合本规范。

**硬规则：** 以后新增一个全局入口，必须先删掉一个；否则把它放进 Lodge 的判断，或放进已有对话框。入口越多，用户越要替产品做决定。

## 原则

1. **表里如一。** 每句话对应真实机制：说验收通过就真有结果证据，说跨厂商就真是两家厂商。样例数据必须标注。
2. **默认即最佳。** 打开就落在 Lodge 常驻对话里；说一句，它判断要交结果还是先聊，再开对应的房。房型不出现在前门；侧栏「＋」默认开工作室，想聊天时点「先聊聊」，不需要先理解房型。
3. **一次一个决定。** 最多一个待你处理的问题，并带推荐答案。对齐阶段自动确认，不向用户提问；需要拍板的分叉只在决策阶段出现。
4. **结果优先。** 首屏先看到目标、进度和结论，过程记录留在房间里，需要时再展开。
5. **渐进披露。** 换执行者、工作文件夹都在高级项里；主路径只有一个决定：要做什么。成员、模型和怎么验都由规划师和验收员自己定。
6. **一切可撤销。** 停止可用；不自动 push、不自动合并、不产生不可逆操作。
7. **安静。** 只在改变下一步时提醒。只有真正等人处理的提问、审批、失败和交付才通知；进度、重试和后台建议不弹，同一间房短时间内不重复。岛是唯一讲故事的地方，不是通知中心；其他进行中的房间缩成一行小岛。
8. **失败说人话。** 说清谁没回应、缺什么、可以怎么继续，不把堆栈丢给人。
9. **一个产品。** 新页面必须像一直在这里：复用已有的字号、颜色、间距、圆角和措辞。
10. **每个状态都要设计。** 默认、悬停、焦点、按下、禁用、空、加载、错误、长文本、窄窗口、明暗主题。
11. **命名，不解释。** 好标签胜过一段说明；按钮写动作，不写流程。
12. **房间各自独立。** 聊天室和工作室谁也不从属于谁；工作目录是第一等输入；两者都是一等门。
13. **成员是身份，身体是载体。** 换身体、换性格不换成员；记录、证据和交接保留。
14. **话是成员说的。** 平台不代写气泡；交接靠房间规则：工作室由系统投递，聊天室按公平顺序；房间只记账和叫醒。
15. **聊天室内容自由，节奏受控。** 成员自己发言，主持定序、收结论；轮次和超时由房间控制，界面不显示「第几轮」。
16. **展开不打扰阅读。** 展开/收起是阅读动作：不自动滚到底、不抢焦点；关闭后焦点回到原控件。
17. **需要用户时，把动作放在眼前。** 系统走不下去时，把动作放在当前房间最显眼的位置，一句人话说清缺什么，一次点击完成。
18. **两条腿都完整。** 聊天室有聊完、有结论、可再来；工作室有目标、证据、交付。
19. **小字只留给必要信息。** 控件已经说清的不重复；小字只留真实错误、非显然后果和必须知道的限制。
20. **记录让人放心，不让人操心。** 房间里只有三个角色的话和结果卡：规划师、执行官、验收员。规划师每轮用自然中文说计划：先结论，再按格式分点——下一步和交给谁、怎么算过、做完是什么样；不套标签、不写内部步骤、口径或系统阶段。系统只做路由和记账，不代写计划、交接或结论；交接、阶段回执和完成记录留在后台账本，不作为成员发言出现在房间里。时间线只保留会让人等待或需要人处理的事：退回交给谁、需要你处理的失败，以及「连接断开、正在自动重试」这类解释停顿的状态——说成一句安静的状态，不写成事故，也不逐次播报重试。后台建议、重复进度、内部计数，以及结果通过、阶段推进、轮次开始、上一轮摘要这类复述性回执不进时间线；技术提醒放在能行动的地方（交付卡、详情）。没有让用户做的事，不要 @ 用户；`@` 只给真实成员。
21. **动作在需要时出现。** 主结果和下一步常驻；复制、转换、逐文件打开、逐条撤回/插话在悬停或键盘聚焦时出现，触屏直接显示。不是把所有动作藏起来，是让主视线只留一个决定。

一句话：好用先于好看，好看来自克制。

## 字号

| 用途 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面 / 对话框标题 | 20 / 26 | 600 |
| 卡片、结果、阶段、结论标题 | 14 / 22 | 600 |
| 正文、聊天 | 14 / 22 | 400 |
| 标签、按钮、说话人 | 13 / 20 | 500；主按钮和说话人 600 |
| 计数、状态、辅助信息 | 12 / 18 | 400 |
| 工作记录、检查、审批、提问的正文 | 13 / 20 | 400 |

只用 400 / 500 / 600 三档。强调先用 600 字重和留白，不靠放大字号；同层已有加粗才升一级字号。成员消息里重要信息用 **加粗**，字号不变；中文标签不要包成行内代码。正文字距 0，标题 `-0.01em`。品牌字标「Lodge」用 Snell Roundhand 22 / 600，它本身就是 Lodge 对话入口；单个加号新建与它同排，房间列表不再重复 Lodge。岛安静时只显示绿点 +「空闲中」，不再重复名字；输入提示里的 Lodge 用手写体，房间列表等功能性正文仍用界面字体。不放图标，也不把岛的黑胶囊当品牌。

## 间距与圆角

- 只用 4 / 8 / 12 / 16 / 24 / 32 的 4px 网格。卡片内边距 12 / 16，结果卡和对话框 24。卡片间距 12，区块 16 / 24。先靠间距分组，再考虑分隔线。
- 按钮、输入框 8；菜单和块 12；结果卡、结论卡、对话框、聊天气泡、输入条 16；胶囊和标签 999。不用 10、14、18、20。

## 颜色

- 所有颜色来自 `ui/src/theme.js` 的 token，不写一次性色值。
- 一个 accent：链接、焦点、选中和主按钮。荧光绿只表示完成和进度，不填充主按钮；警告、危险只表示状态。
- 卡片是平的：1px 细线或淡底色，二选一，不加阴影；只有浮层才投影。
- 灵动岛是唯一例外：玻璃、模糊、双层阴影和弹簧形变只属于它。浅色页面上的岛是深色玻璃；深色页面换成深祖母绿玻璃配暖金边。不挂箭头，两端正圆；进度收在外圈环里，不铺长条。没事收成小药囊，悬停向右长出步骤，有人等你时展开成两行。
- 不给卡片加彩色顶边；等级靠 ink 三层明度、字号和字重，不靠第四种灰。

## 灵动岛

- 休息：216×44，只放当前一步；中间是第几步，外圈绿色进度环。
- 悬停：横向长到 400×54，露出目标、步骤轨和下一步；移开收回。
- 事件：有提醒时一直展开，第二行只放那件事；红色只属于提醒，不属于进度。
- 打开：30 圆角面板，放目标原句、步骤拆解和需要你处理的事。
- 只在状态变化时动一次；尊重 `prefers-reduced-motion`。展开如果只是把同一句话重排，就不该展开。
- 聊天室安静时，岛收成和工作室「已交付」一样大的短胶囊：绿点加房间名，不写「正在聊」；有回合在跑时展开显示状态，结束后停留一小会儿再回到最小，不常驻一条状态。
- 工作室有回合在跑时岛面显示当前步骤；不活动时收成和聊天室一样的小胶囊，只留一个原子状态：`等你决定 / 空闲中 / 已暂停 / 已停止 / 已归档`，停了就是「空闲中」，不把旧步骤继续当成进行中。
- 岛的状态键由共享状态表派生，两种房型共用键、词表分开：

| 状态键 | 工作室 | 聊天室 |
|---|---|---|
| `running` | 当前步骤 / 进行中 | 正在聊 |
| `waiting` | 等你决定 | 聊到这儿了 |
| `idle` | 空闲中 | 还没开始聊 |
| `paused` | 已暂停 | 已暂停，随时接着聊 |
| `stopped` | 已停止 | 已停止 |
| `archived` | 已归档 | 已归档 |
| `done` | 已交付 | —（聊天没有交付） |

- 判定顺序：归档 → 停止/暂停 → 聊天阶段和运行标志 → 等你 → 已交付。归档优先于一切运行态，所以归档的聊天不会再显示「正在聊」或停止键。
- 不画在岛上的：阶段内部的 `blocked/waiting` 细节、轮次的 `planning`、交接的 `working/reviewing`；岛用 barLabel 和侧栏说「要你处理什么」，房间和项目页负责细节。
- 灵宠是《山海经》里「养之可以已忧」的朏朏：白毛白尾、圆脸短腿、一整圈颈鬣；只住在岛上沿，不进入正文。聊天室里它是陪伴，悬停或点它会轻轻跳一下；工作室里它是进度守望，跟着当前步骤走，点它打开工作详情。聊天室给岛和灵宠留出一条上沿，消息从下面开始，不从它身下穿过；安静时它趴在小胶囊上，有回合时跟着岛一起展开。安静时它会眨眼、打哈欠，先沿着整条上沿慢慢逛一段，十秒后趴下歇着，再久睡着（交付后也睡），睡着时呼出的气泡和 z 标记都用金色；鼠标移到岛上，它会走到光标下贴一下、冒爱心，点它也会贴贴并把它叫醒；偶尔飞来一只金色小蝴蝶，它沿着岛沿追两步、扑一下，追不到就让它飞走。浅色下用线稿，耳尖和额头带一点浅橘棕，额头正中压一枚很小的 Lodge 字标；暗色下换成奶白配色，不做纯白反相，免得变成白色剪影；侧身四足线稿站着时四足清楚，移动时整体轻快地走或跑；不说话、不弹气泡、不通知。

## 按钮与输入

- 高度只用 28 / 32 / 36；弹窗主操作实底 accent，卡片和岛里用 accent 淡底；次操作 ghost 或纯文字。
- 一行最多一个主操作，主操作在右。按钮写动作：开工、转成工作室、继续做、回聊天室。
- `@` 只给真实成员和「所有人」做药丸；`@you` 这类不是成员，按普通文字。没有让用户做的事，不要 @ 用户。
- 附件是话的一部分：整窗可拖放、输入框可粘贴，发送前按原比例预览；一条消息最多 10 个附件、总量 40MB。交付里的图片按组摆出，尺寸由验收结论说。
- 输入条只有一个发送位：空输入不显示，有文字出现返回箭头 `↵`，回合在跑时变成实心方块；回合结束方块自动消失，不等「最近活动」超时。点方块只停下这次回复，不暂停房间，输入框继续可用。
- 调整步骤没有弹窗：用户直接在输入框说「退回第 N 步」或「重做第 N 步」，规划师调用 `lodge_gate_rewind_stage`；页面不再出现「补一句再跑 / 退回并重跑」按钮。
- 决策卡是一张单选卡：灰底问题头、整行选项、每个选项带代价、推荐标记和底部「按这个继续」；旁边只有一个「先不做」。同一时间只开一张，选完卡片消失，选择按用户消息落进时间线。
- 成员的挂起在成员行菜单里，叫「先别给 TA 派活」，是持久开关。身体和能力声明在成员卡里，声明不是验证。
- 「回到最新」是辅助动作：28px 圆、1px 细边、降低透明度、不投影；只在离开底部时出现，不压内容。
- 交付后输入框不消失：在空闲的工作室里，发送这句话就是开新一轮，没有额外的提交菜单。旧轮只读，项目页和工作室的「历史」都能回看。
- 点完保持焦点；展开/收起控件留在原位；互斥的两三个选项用滑动开关。

## 卡片与弹窗

- 结果卡、开场卡圆角 16；里面的记录卡 12。不嵌套卡片。
- 聊天、结果、工作记录共用同一条内容宽度；消息卡与聊天正文同宽，头像在说话人行内。
- 聊天发言行在名字后显示两字立场标签（提议 / 质疑 / 收束），只在成员有立场时出现；性格继续用小字放在后面，不抢名字。
- 聊天结论卡只留两个动作：「复制结论」和「转成工作室」，平时收起，悬停或键盘聚焦时出现；触屏没有 hover 时直接显示。排队消息只留「撤回」「插话」，同一套悬停动作。不做逐条展开或逐条重试，房间记录不按消息重写。
- 结果卡的主结果文件和「下载交付记录」留在结果区；「交付说明」「详情」和逐文件「打开」「回聊天室」收成底栏右侧的紧凑图标行，悬停/键盘聚焦时出现，触屏直接显示。检查完直接在下面的输入框说下一轮要做什么，不再放「接着改」按钮。主视线只放一个决定。
- 聊天室成员的性格、说话习惯和固定问题属于固定班底，跨房间不变，建房时不让用户改；成员行只显示今晚的焦点。它只影响说话方式，不是技能、工具或权限。
- 结果卡结构固定：标签/状态 → 标题 → 一句目标 → 验收 → 计数 → 详情。常驻承诺的房间用「本期 · 11月24日」当标题，不把同一句目标每周重抄一遍。次要操作浮在卡片右下角，悬停/聚焦出现，不占正文高度。验收结论按成员发言字号显示；没有实际内容的「理由」不占一行。

## 建工作室

- 只问一件事：要做什么。名字可选，文件夹可选；不出现成员、模型、验收方式或“重新出方案”。
- 开工后房间里只有规划师，先写「目标对齐」；规划师用一张方案和队伍把执行官、验收员和模型定下来，平台开通后直接开始第一步。
- 用户不增删成员；成员坏了只换执行者。侧栏成员菜单保留「换个执行者」「先别派活」，不出现「添加成员」。
- 工作包多了才会多开执行官；两个包碰同一批文件时只开一位，不让人手去合并两个抢同一处的分支。

## 邮箱

- 入口在左下角「你」里：邮箱一行显示「已连接 · 发件邮箱」或「还没连接」，点「连接 / 修改」展开。
- 只问两个字段：发件邮箱、应用密码。常见服务商（126/163/QQ/Gmail/Outlook/iCloud 等）的主机、端口和加密按地址自动认，识别后只显示一行「已识别 126 邮箱」和一句授权码提示，不露主机、端口或加密方式。
- 只有一个「测试」按钮：先保存再发一封测试信；通过后按钮变绿、写「测试通过」，下面一行「已发到 …」。不通过就用一行红字说原因。
- 没有单独的「保存」按钮：底部主按钮是「保存并关闭」（有未保存内容时），填完直接关窗也会先保存。保存成功后主按钮安静下来，只写「完成」。
- 收件人默认是自己；要给某一期发到别的地址，在承诺的「改一下」里填。认不出的服务商直接说明只支持常见邮箱，更少见的服务器用 `LODGE_SMTP_URL`。
- 密码不回显、不回传；小字只说一句「只存在这台电脑，不进房间」。
- 断开是一行文字按钮，不做二次确认。

## 常驻承诺

- 交付卡只出现一次「以后每周也这样」；点一下用这次目标生成一件“说好的事”，默认周五 18:00，不出现 cron 或日程页。承诺自己开的那一期跑完就交付，不停在人的「确认」上。
- 房间顶部一行：`说好的 <一句话>` + `每周五 18:00 · 下次 11月27日 18:00 · 还没做`；主操作「现在跑一次」，`⋯` 里「改一下 / 暂停 / 不做了」。暂停后主操作是「恢复」，停了是「重新开始」。
- 「改一下」是唯一表单：做什么、每周/每天、周几、几点、留在房间或发到邮箱。选邮箱时再选「每次都发 / 有变化才发」；邮箱没接上就在保存时说清楚，不假装能发。
- 只是房间的一行；结果仍是时间线主角。到点房间忙就跳过这一期，不排队、不追着人；关掉应用错过的，下次打开补一次，并说一句「这一期是补上的」。卡片说「第一期 / 上次有变化 / 上次没变化」，不和上一期比就不编。
- 不可逆确认走正中 alert：宽 360，标题不重复对象名，正文一句后果，危险动作红色实心，焦点不默认停在危险按钮。
- 审批卡先写谁想做什么、要动的东西和一句后果；命令折在「看命令」。系统不建议时，「先别做」是主按钮，危险动作不做视觉强调。
- 表单和长内容贴顶，宽 440–600，内部滚动；Esc、点外部、取消都能退出，提交中除外。
- 轻量菜单贴触发点，关闭后焦点回到触发按钮。同一时间只开一层弹层。

## 动效与状态

- 只在状态变化时动，不循环；统一弹簧曲线，内容分层错开 20–40ms；减少动态时全部关闭。
- 有人在跑时，房间始终有一行活状态：谁、第几步、在跑什么、多久；信号来自房间自己的交接和活动，基座 `working` 只是补充；有未结束交接时输入条出现停止键。
- 工具调用不另开面板：连续调用在发生的位置收成一行，跑着带活点和时长，跑完保持收起；展开是中文动作（读了 / 跑了 / 改了 / 提交了判定），费用与记忆在最新一组里。
- 一轮交付后岛收成一行「已交付 · N 步」，但房间本身仍是空闲，可以接着开下一轮；悬停或键盘聚焦展开目标原句。结果卡就是工作记录时间线的最后一条，工作记录不折叠；检查完直接在下面继续下一轮，旧结果留在记录里。聊天室和工作室的成员都收在房间 `⋯` 菜单的「成员」里，点开是贴着房间的紧凑成员面板；聊天室不给「历史」，菜单只放各自房型有能力的动作。
- 验收结论是一张短卡：PASS/REJECT 加一句理由，证据折在「理由」；详细分析不另发聊天。
- 用户消息只保留右对齐气泡，不加头像。空状态一句话加一个动作；断线有可见提示，恢复后清掉旧状态。
- 多张待确认卡显示剩余数量；同一时刻只把最该处理的那张推到前面。

## 产品语言

- 岛是唯一讲故事的地方：目标、当前节点、在等你的事；其他界面按需出现，不抢叙事。
- 一个概念只用一个词：房间、成员、步骤、检查、结果、结论；内部词不上主界面。
- 一句话说一件事；不写流程旁白或实现旁白（副本、并行、重启后、未启动）。
- 状态不重复：标题、卡片、底栏只保留一个完成状态。
- 独立复核按实际来源写：同一家写「模型自查」，不同厂商才写「独立复核」。
- 错误说清发生了什么、下一步怎么办；原始报错、状态码和堆栈只进 detail 与日志。
- 一间房要像看群聊一样看懂谁在做什么；细节折起来，不删掉。
- 不做单独的确认仪式：验收通过就算完成，房间不关闭；交接就是一句 @，不做交接卡。

用词表和禁用词以 `shared/product-copy.js` 为准，改文案后跑 `npm test`。
