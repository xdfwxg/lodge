# Lodge 设计语言

Lodge 是一间房：说清楚，或做出来。工作室的界面回答三件事：现在在做什么、谁在做、结果怎么样；聊天室只回答：在聊什么、谁在说、聊到哪儿了。所有界面按这份文件走。

> 本文回答：界面和交互怎么做——字号、间距、颜色、组件、状态、文案。产品判断与**原则总表**见 [../Lodge.md](../Lodge.md#原则总表)；本文的原则是它在界面层的展开。

## 原则

1. **表里如一。** 每句话对应真实机制：说检查通过就真有退出码，说跨厂商就真是两家厂商。样例数据必须标注。
2. **默认即最佳。** 打开就落在 Lodge 常驻对话里；说一句，它判断要交结果还是先聊，再开对应的房。房型不出现在前门；完整对话框和「更多选项」仍在。
3. **一次一个决定。** 最多一个待你处理的问题，并带推荐答案。对齐阶段自动确认，不向用户提问；需要拍板的分叉只在决策阶段出现。
4. **结果优先。** 首屏先看到目标、进度和结论，过程记录留在房间里，需要时再展开。
5. **渐进披露。** 换模型、工作文件夹、先出方案都在高级项里；主路径只有三个决定：做什么、谁来做、怎么验收。
6. **一切可撤销。** 停止可用；不自动 push、不自动合并、不产生不可逆操作。
7. **安静。** 只在改变下一步时提醒。岛不是通知中心；其他进行中的房间缩成一行小岛。
8. **失败说人话。** 说清谁没回应、缺什么、可以怎么继续，不把堆栈丢给人。
9. **一个产品。** 新页面必须像一直在这里：复用已有的字号、颜色、间距、圆角和措辞。
10. **每个状态都要设计。** 默认、悬停、焦点、按下、禁用、空、加载、错误、长文本、窄窗口、明暗主题。
11. **命名，不解释。** 好标签胜过一段说明；按钮写动作，不写流程。
12. **房间各自独立。** 聊天室和工作室谁也不从属于谁；工作目录是第一等输入；两者都是一等门。
13. **成员是身份，身体是载体。** 换身体、换性格不换成员；记录、证据和交接保留。
14. **话是成员说的。** 平台不代写气泡；交接靠 `@`；房间只记账和叫醒。
15. **聊天室内容自由，节奏受控。** 成员自己发言，主持定序、收结论；轮次和超时由房间控制，界面不显示「第几轮」。
16. **展开不打扰阅读。** 展开/收起是阅读动作：不自动滚到底、不抢焦点；关闭后焦点回到原控件。
17. **需要用户时，把动作放在眼前。** 系统走不下去时，把动作放在当前房间最显眼的位置，一句人话说清缺什么，一次点击完成。
18. **两条腿都完整。** 聊天室有聊完、有结论、可再来；工作室有目标、证据、交付。
19. **小字只留给必要信息。** 控件已经说清的不重复；小字只留真实错误、非显然后果和必须知道的限制。
20. **记录让人放心，不让人操心。** 时间线保留交接链和会让人等待或需要人处理的事：阶段确认、谁交给谁、退回交给谁、需要你处理的失败，以及「连接断开、正在自动重试」这类解释停顿的状态——说成一句安静的状态，不写成事故，也不逐次播报重试。后台建议、重复进度、内部计数不进时间线；技术提醒放在能行动的地方（交付卡、详情）。没有让用户做的事，不要 @ 用户；`@` 只给真实成员。

一句话：好用先于好看，好看来自克制。

## 字号

| 用途 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面 / 对话框标题 | 20 / 26 | 600 |
| 卡片、结果、阶段、结论标题 | 16 / 24 | 600 |
| 正文、聊天 | 16 / 24 | 400 |
| 标签、按钮、说话人 | 13 / 20 | 500；主按钮和说话人 600 |
| 计数、状态、辅助信息 | 12 / 18 | 400 |
| 工作记录、检查、审批、提问的正文 | 13 / 20 | 400 |

只用 400 / 500 / 600 三档。强调先用 600 字重和留白，不靠放大字号；同层已有加粗才升一级字号。正文字距 0，标题 `-0.01em`。品牌字标「Lodge」用 Snell Roundhand 22 / 600，它本身就是 Lodge 对话入口；单个加号新建与它同排，房间列表不再重复 Lodge。岛安静时只显示绿点 +「空闲中」，不再重复名字；输入提示里的 Lodge 用手写体，房间列表等功能性正文仍用界面字体。不放图标，也不把岛的黑胶囊当品牌。

## 间距与圆角

- 只用 4 / 8 / 12 / 16 / 24 / 32 的 4px 网格。卡片内边距 12 / 16，结果卡和对话框 24。卡片间距 12，区块 16 / 24。先靠间距分组，再考虑分隔线。
- 按钮、输入框 8；菜单和块 12；结果卡、结论卡、对话框、聊天气泡、输入条 16；胶囊和标签 999。不用 10、14、18、20。

## 颜色

- 所有颜色来自 `ui/src/theme.js` 的 token，不写一次性色值。
- 一个 accent：链接、焦点、选中和主按钮。荧光绿只表示完成和进度，不填充主按钮；警告、危险只表示状态。
- 卡片是平的：1px 细线或淡底色，二选一，不加阴影；只有浮层才投影。
- 灵动岛是唯一例外：玻璃、模糊、双层阴影和弹簧形变只属于它。浅色页面上的岛是深色玻璃；深色页面换成深祖母绿玻璃配暖金边。不挂箭头，两端正圆；进度收在外圈环里，不铺长条。没事收成小药囊，悬停向右长出步骤，有人等你时展开成两行。
- 不给卡片加彩色顶边；等级靠 ink 三层明度、字号和字重，不靠第四种灰。

## 灵动岛

- 休息：216×44，只放当前一步；中间是第几步，外圈绿色进度环。
- 悬停：横向长到 400×54，露出目标、步骤轨和下一步；移开收回。
- 事件：有提醒时一直展开，第二行只放那件事；红色只属于提醒，不属于进度。
- 打开：30 圆角面板，放目标原句、步骤拆解和需要你处理的事。
- 只在状态变化时动一次；尊重 `prefers-reduced-motion`。展开如果只是把同一句话重排，就不该展开。
- 聊天室安静时，岛收成和工作室「已交付」一样大的短胶囊：绿点加房间名，不写「正在聊」；有回合在跑时展开显示状态，结束后停留一小会儿再回到最小，不常驻一条状态。

## 按钮与输入

- 高度只用 28 / 32 / 36；弹窗主操作实底 accent，卡片和岛里用 accent 淡底；次操作 ghost 或纯文字。
- 一行最多一个主操作，主操作在右。按钮写动作：开工、转成工作室、继续做、回聊天室。
- `@` 只给真实成员和「所有人」做药丸；`@you` 这类不是成员，按普通文字。没有让用户做的事，不要 @ 用户。
- 附件是话的一部分：整窗可拖放、输入框可粘贴，发送前按原比例预览；一条消息最多 10 个附件、总量 40MB。交付里的图片按组摆出，尺寸由验收结论说。
- 停止只有一个：有回合在跑时，输入框的发送键变成方形停止键；成员的挂起在成员行菜单里，叫「先别给 TA 派活」，是持久开关。身体和能力声明在成员卡里，声明不是验证。
- 交付后输入框不消失：发送是问规划师，旁边「接着改」用当前这句话开下一版；旧版只读，侧栏标 `v2`，结果卡和房间头能互相打开上一版、下一版。
- 点完保持焦点；展开/收起控件留在原位；互斥的两三个选项用滑动开关。

## 卡片与弹窗

- 结果卡、开场卡圆角 16；里面的记录卡 12。不嵌套卡片。
- 聊天、结果、工作记录共用同一条内容宽度；消息卡与聊天正文同宽，头像在说话人行内。
- 结果卡结构固定：标签/状态 → 标题 → 一句目标 → 检查 → 计数 → 详情 → 底栏。底栏左边签字或来源，右边操作。
- 不可逆确认走正中 alert：宽 360，标题不重复对象名，正文一句后果，危险动作红色实心，焦点不默认停在危险按钮。
- 表单和长内容贴顶，宽 440–600，内部滚动；Esc、点外部、取消都能退出，提交中除外。
- 轻量菜单贴触发点，关闭后焦点回到触发按钮。同一时间只开一层弹层。

## 动效与状态

- 只在状态变化时动，不循环；统一弹簧曲线，内容分层错开 20–40ms；减少动态时全部关闭。
- 房间完成后岛收成一行「已交付 · N 步」，悬停或键盘聚焦展开目标原句；成员只在侧栏房间下面。
- 验收结论是一张短卡：PASS/REJECT 加一句理由，证据折在「理由」；详细分析不另发聊天。
- 用户消息只保留右对齐气泡，不加头像。空状态一句话加一个动作；断线有可见提示，恢复后清掉旧状态。
- 多张待确认卡显示剩余数量；同一时刻只把最该处理的那张推到前面。

## 产品语言

- 用房间、成员、交接、检查、结果、结论；不用身体、引擎、产物、返工、审批这类内部词。
- 一句话说一件事；不写流程旁白，不写实现旁白（副本、并行、重启后、未启动）。
- 状态不重复：标题、卡片、底栏只保留一个完成状态。
- 独立复核按实际来源写：同一家写「模型自查」，不同厂商才写「独立复核」。
- 错误说清发生了什么、下一步怎么办；原始英文报错、状态码、堆栈写进 detail 和日志，不进出界面。
- 一间房要像看群聊一样看懂谁在做什么；记录不切章节、不截窗口、不隐藏阶段结论，细节折起来而不是删掉。
- 不做签字：验收通过就继续，房间不关闭；交接就是一句 @，不做交接卡。

## 提交前检查

`npm test`、`npm run build`、`npm run test:ui`。Playwright + axe 覆盖首屏、结果卡、目标面板和窄屏暗色；检查明暗主题、窄窗口、键盘焦点、减少动态效果，并对照本文件检查字号、间距、圆角、按钮、状态和文案。
