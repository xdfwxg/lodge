# Lodge · 工作室、轮次与项目（一页设计）

> 本文回答：跨月、跨年的工作，怎么在 Lodge 里长期推进，而不把每件事都变成一间新房。

## 一句话

**工作室是长期工作间，轮次是这一轮要交付的事，项目是轮次的分组。**

不是第四种引擎，也不是第四种角色。执行和验收仍在规划师/执行官/验收员三个人身上。

## 用户打开后 30 秒

看到三件事：

1. 这个工作室现在在这一轮的哪里——目标、阶段、状态。
2. 已经做完哪几轮，结果能不能打开。
3. 下一件事要做什么；如果有真正的分叉，先选一个方向。

不再先看到几百条历史消息，也不需要在每个 bug 后新建一间房。

## 三层

| 对象 | 是什么 | 不做什么 |
|---|---|---|
| 工作室（room） | 长期容器：成员、工作区、历史、所属项目 | 不因为一轮目标完成而结束 |
| 轮次（work round） | 一次可交付的目标，可小可大：bug、功能、阶段 | 不覆盖上一轮；完成只结束自己 |
| 项目（project） | 轮次的分组和北极星 | 不执行、不验收、不保存证据副本 |
| 决策卡 | 开工前 1–2 个真正影响方案的选择 | 不做问卷、不无限追问 |

## 一条路径

1. **开工作室**：选成员、工作区；工作室进入空闲，不强制绑定一个目标。
2. **说这一轮要什么**：一句话目标；有分叉时规划师先出 1–2 个决策，每个 2–4 个选项、代价和推荐。
3. **排阶段**：选完方向才拆阶段；没有分叉就直接排。
4. **执行与验收**：证据、结论、交付都归这一轮；旧轮只读。
5. **这一轮完成**：工作室回到空闲；同一成员、同一工作区可以开下一轮。
6. **回看旧轮**：工作室头部的「历史」列出这个工作室的所有轮，里面有项目入口；项目页也按项目列出。点已结束的轮次打开只读记录，不进入当前轮。
7. **换项目**：同一工作室可以给另一个项目开轮；项目页按项目聚合轮次。
8. **改目标**：旧轮标成已作废，新轮从新目标开始；旧证据不算新目标。

## 数据

- `room`：长期字段、成员、工作区、`state`（`idle/active/paused/stopped`）、`activeRoundId`、`lastRoundId`、`defaultProjectId`。
- `work_round`：`goal`、`plan`、`stages`、`gate`、`decisions`、`constraints`、`usage`、`delivery`、时间戳、提交；`status` 为 `planning/active/completed/rejected/superseded/stopped`。
- `project`：名字、北极星、状态。
- `messages.work_round_id`、`assignment.work_round_id`：轮次隔离的硬边界；证据和 verdict 正文仍在消息里。
- 旧轮通过 `GET /api/rooms/:id/rounds/:roundId` 按轮取回房间视图和消息；只读，不写任何状态。
- 房间目录按轮次保存 `rounds/<roundId>/GOAL.md`、`CONCLUSION.md` 和证据；房间级 `transcript.jsonl` 是恢复镜像。
- 旧数据直接清掉，不做迁移、不留兼容字段。

## 不做什么

- 不新增第四种房间引擎或第四种底层角色。
- 不把「目标完成」写成「房间结束」。
- 不把「停止回复」做成房间级暂停；停的是当前回答，房间继续可用。
- 不把项目做成 `nextRoomId` 房间链；项目是轮次分组。
- 不把 routines/subrooms 塞进第一版；它们不是手动开轮的路径。
- 不引外部 issue tracker 当主库；项目页只读轮次事实。
- 不自动 commit / push / 开 PR。

## 第一版验收

- 同一工作室连续做两轮，旧轮可回看且只读。
- 一轮完成只把工作室送回空闲，不新建房间。
- 项目页按轮次聚合，能打开某一轮的工作室，能开下一轮。
- 有真实分叉时出决策卡，选完才排阶段；没有分叉不硬问。
- 旧轮证据、决定、费用不混进新轮。
- 窄屏、暗色、空状态下都能回答“现在在哪、下一步是谁”。
