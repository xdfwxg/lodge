# Lodge · 项目房（一页设计）

> 本文回答：跨月、跨年的复杂目标，怎么在 Lodge 里长期推进，而不把一间工作室拉成聊天记录。

## 一句话

**项目房是工作室的一种房间能力，不是第四种引擎，也不是第四种角色。**

它只做长期协调：北极星、路线、当前阶段、决策、风险和预算。  
每个阶段仍是一间普通的子工作室，执行和验收仍在规划师/执行官/验收员三个人身上。

## 用户打开后 30 秒

看到三件事：

1. 这个项目现在要做成什么——一句话北极星。
2. 现在在哪一段——当前阶段、负责人、状态。
3. 下一步需要谁——继续、换路线，还是等人拍板。

不再先看到几百条历史消息。

## 结构

| 对象 | 是什么 | 不做什么 |
|---|---|---|
| 项目房 | 长期存在的协调房间，一个规划师 | 不执行、不验收、不写交付文件 |
| 阶段 | 路线上的一个有边界的目标 | 不把整个项目塞进一个阶段 |
| 子工作室 | 现有工作室，完整三角色 | 不继承项目房的聊天历史，只拿阶段 brief |
| 阶段成果 | 子工作室的交付卡、证据、检查、提交 | 不复制进项目房，只留引用 |
| 决策与风险 | 项目级的事实：为什么改路线、下一次注意什么 | 不写成长篇会议纪要 |

## 一条路径

1. **定北极星**：用户说清长期要什么，规划师只问一个最关键的问题。
2. **排路线**：先列 3–7 个阶段，每个阶段有目标、验收和大致产出；不一次排完所有细节。
3. **开当前阶段**：项目房创建一间子工作室，brief 包含阶段目标、验收、项目约束和已有成果引用。
4. **子工作室交付**：执行、证据、独立验收都在子工作室完成；项目房只收结果。
5. **项目房收口**：记录阶段成果、决策、风险、费用；当前阶段通过后，下一阶段才解锁。
6. **人改路线**：阶段失败、目标变化、预算变化时，由人决定继续、重排或停止；模型不替人把路线跑三年。

## 界面

一屏只留一个主要决定：

- **顶部**：北极星 + 当前阶段。
- **中间**：阶段列表，当前阶段展开，已完阶段收成一行。
- **右侧/下方**：待你决定的事、阶段成果链接、项目级风险。
- **默认折叠**：所有历史聊天和子房间过程；需要时再打开，不铺满主屏。

项目房没有“第几条消息”，只有“第几阶段、现在到哪、下一步是谁”。

## 数据

项目房仍是 `room`，增加一组只读/协调字段，不新增执行引擎：

- `project: { northStar, phases[], currentPhase, decisions[], risks[], budget }`
- `phase`: `{ id, goal, state, childRoomId, acceptance, deliverable, cost, startedAt, acceptedAt }`
- `state`: `planned / active / accepted / blocked / cancelled`
- 子工作室通过现有 `childRoomId`、assignment、delivery 和 evidence 关联；项目房不复制证据正文。

阶段只允许一个 `active`。并行阶段不进第一版，避免把长期问题变成调度器。

## 不做什么

- 不新增第四种房间引擎或第四种底层角色。
- 不把项目房做成无限长的聊天室。
- 不自动排三年路线；路线变更必须是人拍板。
- 不把 GitHub/Linear 当主库；项目房仍是唯一真相。
- 不自动 commit / push / 开 PR。
- 不在第一版做甘特图、资源排班、跨项目依赖。

## 第一版验收

- 从一间已交付的工作室升级为项目房，不丢原目标、成员和交付链。
- 项目房能排 3 个阶段，同一时间只有一个阶段在跑。
- 每个阶段是一间子工作室，交付卡和证据能回到项目房索引。
- 阶段失败时项目房停在该阶段，不自动开下一阶段。
- 项目房页面在窄屏、暗色、空状态下都能回答“现在在哪、下一步是谁”。
- 项目房的历史只增决策、风险和阶段索引；子工作室过程不复制。

## 下一步

先做“项目房 + 3 个阶段 + 子工作室索引”的最小闭环。  
不要先做路线图编辑器、预算系统或并行调度；等真实项目跑过三个阶段，再决定下一层。
